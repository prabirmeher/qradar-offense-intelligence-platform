    Known Issues¶

    This page tracks known issues in shipped releases, along with manual workarounds you can apply while waiting for the fix to reach your appliance. Each entry lists the affected version(s) and the release where the issue is resolved.

    If you hit something not listed here, see Feedback & Contributing.

    Analysis output truncated on complex offenses¶

    Affected versions: v1.0.0
    Status: Fixed in upcoming release v1.1.0

    Symptom¶

    AI analysis on offenses with several triggering rules and a large number of events sometimes returns a truncated or malformed response — the output cuts off mid-section, or one of the 7 expected sections is missing entirely.

    Cause¶

    The LLM's context window (--ctx-size) is fixed at 4,096 tokens in v1.0.0. Offenses with 3 or more triggering rules and ~25+ events can build a prompt exceeding 11,000 tokens, which gets silently truncated by the model server before generation.

    Workaround (v1.0.0 only)¶

    Upgrading to v1.1.0 resolves this automatically. If you can't upgrade immediately, you can raise the context window manually:

    Requires root/console access to the QRadar appliance

    This workaround edits a file inside the app's container. Changes made this way do not survive an app reinstall or upgrade — you'll need to reapply them, or upgrade to v1.1.0+ to make the fix permanent.

    1. SSH into the QRadar Console (or the host running the App Framework) as root.
    2. Find the app instance ID (IID) for the Offense Intelligence app: 
      echo 0 | /opt/qradar/support/qappmanager
    3. Connect to the container. If the app is running on an App Host, SSH to that App Host first, then run: 
      /opt/qradar/support/recon connect <IID>
      where <IID> is the app instance ID from step 2 (e.g. 1407).
    4. Edit the llama-server startup script: 
      vi /opt/app-root/container/service/llama_server.sh
      Change the --ctx-size value from 4096 to 20000, then save and exit.
    5. Restart the LLM service so the new setting takes effect: 
      supervisorctl restart llama_server
    6. Confirm the AI Ready indicator turns green again, then re-run analysis on a previously affected offense to verify the full 7-section output returns.

    Note: Raising --ctx-size to 20,000 increases the LLM's memory footprint (KV cache) by roughly 1 GB. This is accounted for within the standard 8 GB app memory allocation and does not require a manifest change.
