    Changelog¶

    v1.0.0 — May 2026¶

    Initial release of QRadar Offense Intelligence.

    AI Analysis Engine¶

    • On-device Qwen3.5-9B Model — no cloud dependency, zero data egress
    • 5-phase analysis pipeline: rule XML fetch, event sampling, historical correlation, false positive pre-screening, LLM inference
    • Structured 7-section output: Verdict, Why This Rule Fired, Severity Assessment, Likely Attack Vector, Recommended Immediate Actions, False Positive Tuning, Investigation Steps
    • Analysis queue with real-time position tracking and priority for human-triggered jobs
    • AI-generated response tasks extracted from analysis output
    • AI-generated executive summary (incident report) from cached analysis
    • Auto-triage: configurable automatic queuing of new offenses by magnitude/severity threshold
    • Configurable inference timeout (default: 600 seconds)

    MITRE ATT&CK Integration¶

    • Automated technique tagging via on-device LLM, validated against local ATT&CK knowledge base
    • Local ATT&CK database built from STIX 2.1 bundle — works fully offline
    • Per-offense analyst overrides with team knowledge base promotion
    • Category-to-technique mapping management with confidence scoring
    • Kill chain tactic progression bar on offense detail

    Attack Campaign Detection¶

    • BFS graph clustering of related offenses by shared detection rule or attacker source
    • Deterministic campaign naming (no LLM required)
    • Kill chain progression assembled from MITRE tags across all member offenses
    • Campaign status tracking (active/closed), severity, date range, and analyst assignments
    • Lateral movement detection and causal chain flagging
    • Campaign banner on Offense Detail linking back to the campaign
    • Nightly scheduled detection with on-demand trigger

    Offense Relationship Graph¶

    • Interactive vis-network graph with physics-based force layout (forceAtlas2Based)
    • Five investigative lenses: Rule Topology, Attacker Topology, Target Topology, Campaign Topology, Lateral Movement
    • Pre-computed pairwise relationship scoring across 5 dimensions (stored in offense_relationships)
    • Composite scoring: shared rules (35%), attacker source (30%), networks (15%), category+time (12%), lateral hop (8%)
    • Auto-recommendation of strongest lens per offense
    • Directed hierarchical layout for lateral movement chains
    • Node detail panel with match reason chips

    Investigation Workspace¶

    • Collaborative rich-text notes synced back to QRadar offense notes
    • Evidence file attachments (TXT, LOG, CSV, PDF, DOCX, PNG, JPG) with configurable size limit
    • IOC artifact tracking with type categorisation and context field
    • Response task management with completion tracking and audit
    • SOP Template playbooks — define once, apply in one click with automatic offense matching

    Offense Lifecycle Management¶

    • Structured lifecycle stages: Triage → Investigation → Containment → Closed
    • Offense assignment with QRadar user directory integration
    • Closure reason selection with sync back to QRadar
    • Tamper-evident audit trail for every action (actor, event type, message, timestamp)
    • Global Audit Trail page with cross-offense activity view

    Analytics & SLA¶

    • MTTD, MTTR, MTTA trend charts
    • SLA thresholds configurable per severity tier (Critical/High/Medium/Low)
    • SLA breach and at-risk notifications in persistent bell menu
    • Individual notification dismissal with reason logging
    • Analyst workload, stalled case, top attack source, severity breakdown, age distribution dashboards
    • Configurable at-risk threshold percentage and notification retention

    Scheduler¶

    • Built-in job scheduler with configurable daily run times
    • Jobs: Campaign Detection (04:00), MITRE ATT&CK Tagger (03:00), SLA Breach Checker (00:00), Closed Offense Reconciliation (02:00)
    • On-demand job trigger with run history, duration, and summary tracking

    Performance & Architecture¶

    • Local SQLite cache — offense list and detail load from on-device storage, not live QRadar API calls
    • Carbon Design System (IBM) frontend — dark theme
    • All offense data served via local cache; QRadar API called only for sync, notes write-back, and user list
    • Air-gap capable — MITRE ATT&CK bundle upload, model file manual copy supported
